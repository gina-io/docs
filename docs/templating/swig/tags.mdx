# Tags

Tags control flow, define reusable structures, and orchestrate template inheritance. Each tag is written between `{% … %}` markers. Tags that open a block must be closed with `{% end<name> %}`.

In a `set`, `if`, `elseif`, `for`, `include` or `filter` argument a filter applies to the operand just before it, as in `{{ }}` output. Up to 2.9.10 a filter after a function or method call in a `set`, `if`, `elseif` or `for` argument applied to everything before it: `{% if z and f(x)|upper %}` tested `(z and f(x))|upper`, and `{% set y = a + f(x)|upper %}` upper-cased `a` too. In 2.9.10 a filter after a parenthesized operand, as in `{% set y = (x)|upper %}`, and a filter in an `include` path, as in `{% include name|default("p.html") %}`, failed to compile; both work since 2.9.11.

## autoescape

Override the global `autoescape` option for a block.

```swig
{% autoescape false %}
  {{ raw_html }}
{% endautoescape %}

{% autoescape 'js' %}
  var msg = "{{ user.name }}";
{% endautoescape %}
```

The argument is passed to the [`e`](./filters#e--escape) filter. `true`, `false`, and a string type (`'html'`, `'js'`, …) are accepted.

## block

Declares a named override point inside a template that is being extended.

```swig
{# layout.html #}
<title>{% block title %}My Site{% endblock %}</title>

{# page.html #}
{% extends "layout.html" %}
{% block title %}Contact — My Site{% endblock %}
```

Blocks must have unique names within a template: what a repeated name renders is undefined, though since `2.9.12` it renders alike on the two [render paths](./loaders#async-loaders) in most shapes. Use [`parent`](#parent) inside an overriding block to emit the parent's content.

A block nested in another block is a definition of its own name, so an extending template can override it without overriding the block around it. Since `2.9.12` this also holds for a block nested in any block of the extending template, even when the root has no block for the enclosing one: over `<{% block b %}P{% endblock %}>`, the child `{% extends "base.html" %}{% block zz %}{% block b %}N{% endblock %}{% endblock %}` renders `<N>`, where it rendered `<P>` before.

## else

Secondary branch inside [`if`](#if) and [`for`](#for). Inside `for`, it runs when the iterable is empty or missing:

```swig
{% if user.active %}
  Welcome.
{% else %}
  Please log in.
{% endif %}

{% for item in items %}
  <li>{{ item }}</li>
{% else %}
  <p>No items.</p>
{% endfor %}
```

## elseif

Alias: `elif`. Chain multiple conditions inside an `if`:

```swig
{% if x < 0 %}
  Negative
{% elseif x === 0 %}
  Zero
{% else %}
  Positive
{% endif %}
```

## extends

Declares a parent template. Must be the first statement in the child template.

```swig
{% extends "layouts/base.html" %}
```

The parent path may be **dynamic** — `{% extends layout_var %}` or any expression — but a dynamic parent resolves only on the [async render path](./loaders#async-loaders) (`renderFile(path, locals, cb)` against a loader with `loader.async === true`). On the synchronous render path the parent is resolved at compile time, so it must be a string literal.

An extends cycle (`a.html` extends `b.html`, which extends `a.html`) fails with `Illegal circular extends of "<name>".` on both render paths. On the async render path, where it fails since `2.9.5`, a dynamic parent that names the template itself fails the same way.

The child's non-block content is discarded — only `{% block %}` overrides and block-level tags (`set`, `import`, `macro`, `extends`) survive. See [template inheritance](./getting-started#template-inheritance).

## filter

Apply a filter to every string emitted inside the block.

```swig
{% filter upper %}
  Hello, {{ user.name }}.
{% endfilter %}
```

Accepts filter arguments:

```swig
{% filter replace("a", "A", "g") %}
  banana
{% endfilter %}
```

Since 2.9.11 the arguments may hold filters, as in `{% filter replace("a", x|upper) %}`, and empty parentheses are accepted, as in `{% filter upper() %}`; 2.9.10 failed to compile both.

## for

Iterate over arrays, objects, or strings.

```swig
{% for item in items %}
  {{ item }}
{% endfor %}

{% for key, value in obj %}
  {{ key }}: {{ value }}
{% endfor %}
```

Inside the loop, `loop` exposes:

| Property | Meaning |
| --- | --- |
| `loop.index` | 1-based iteration counter |
| `loop.index0` | 0-based iteration counter |
| `loop.revindex` | Reverse 1-based |
| `loop.revindex0` | Reverse 0-based |
| `loop.first` | `true` on the first iteration |
| `loop.last` | `true` on the last iteration |
| `loop.key` | Key for object iteration; same as `index0` for arrays |
| `loop.length` | Total number of iterations |

Use [`else`](#else) for the empty case.

## if

Conditional. Supports `and`, `or`, `not`, comparison operators, `in`, and the `? :` / `?:` [conditional operators](./syntax#operators).

```swig
{% if user and user.active %}…{% endif %}
{% if "admin" in user.permissions %}…{% endif %}
{% if user.roles.indexOf("admin") !== -1 %}…{% endif %}
{% if not items %}Empty.{% endif %}
```

`in` tests a key: a property name of an object or an index of an array. To test an item of an array or a substring of a string, use `indexOf`, as in the `user.roles` example above.

Branch with [`elseif`](#elseif) / [`else`](#else).

## import

Load macros from another template as a namespace object. Does not render the imported template.

```swig
{% import "forms.html" as forms %}
{{ forms.input("email") }}
```

The alias must be a simple identifier. Reserved names (`__proto__`, `constructor`, `prototype`) are rejected at parse time — see [Security](./security).

A macro can also call macros that *its own file* imported — those imports are
set up when the macro runs, recursively across import depth:

```swig
{# buttons.html #}
{% import "icons.html" as icons %}
{% macro save() %}<button>{{ icons.disk() }} Save</button>{% endmacro %}

{# page.html #}
{% import "buttons.html" as buttons %}
{{ buttons.save() }}
```

:::note
An import alias occupies the template's variable namespace: it overrides a
context variable of the same name, so pick alias names that don't collide with
your locals. The aliases an imported file sets up for itself stay out of the
template that imports it, on the sync path and, since `2.9.6`, on the
[async render path](./loaders#async-loaders). On the sync path they stayed
reachable through the importing alias until `2.9.7`: now
`{{ buttons.icons.disk() }}` renders nothing on both paths, while
`buttons.save()` still uses `icons`.
:::

## include

Inline another template. By default the current context is shared:

```swig
{% include "header.html" %}
```

Add variables with `with` — the included template sees them on top of the current context:

```swig
{% include "item.html" with data %}
```

Add `only` to hide the rest of the current context — the included template then sees just the `with` object:

```swig
{% include "item.html" with data only %}
```

Suppress errors for missing files with `ignore missing`:

```swig
{% include "optional.html" ignore missing %}
```

Files are resolved through the active [loader](./loaders).

A template may include itself, for a recursive structure such as a tree, as long as the recursion ends. On the async render path a render fails once 1000 templates are in progress (since `2.9.5`, see [Async loaders](./loaders#async-loaders)); on the sync render path a deep recursion ends at the JavaScript stack limit.

## macro

Define a reusable mini-template.

```swig
{% macro input(name, value, type) %}
  <input type="{{ type }}" name="{{ name }}" value="{{ value|e }}">
{% endmacro %}

{{ input("email", user.email) }}
```

Macros are in scope for the rest of the current template and exported to any template that [`import`](#import)s the file. Macro names are validated — reserved names are rejected (see [Security](./security)).

## parent

Inside an overriding `{% block %}`, emit the parent block's rendered content.

```swig
{% block head %}
  {% parent %}
  <link rel="stylesheet" href="page.css">
{% endblock %}
```

Only valid inside a block that overrides an inherited one.

Since `2.9.12`, blocks follow one chain of definitions per name, nested blocks included, on both render paths: `{% parent %}` renders the next definition of its block's name, and a block rendered through `{% parent %}` keeps the overrides of the blocks nested in it. With the layout `<{% block o %}O[{% block i %}I{% endblock %}]{% endblock %}>`, and each child starting with `{% extends "base.html" %}`:

| Child blocks | Renders |
| --- | --- |
| `{% block i %}C{% parent %}{% endblock %}` | `<O[CI]>` |
| `{% block o %}X{% parent %}{% endblock %}{% block i %}C{% endblock %}` | `<XO[C]>` |
| `{% block o %}Y{% block i %}C{% parent %}{% endblock %}{% endblock %}` | `<YCI>` |

A block that renders itself through a nested block or `{% parent %}` fails with an error naming the block when the render reaches it.

## raw

Emit verbatim content — the parser does not tokenize inside a `raw` block. Useful for embedding other template syntaxes or documentation examples.

```swig
{% raw %}
  This {{ will }} not {% be %} evaluated.
{% endraw %}
```

## set

Declare or update a context variable. Valid at the top of a template even when extending. The variable lives in the render's context, a copy of the locals made at the top of the render (since `2.9.6`), so it does not reach the object the caller passed; a dotted set such as `{% set site.user = who %}` still writes into the object `site` holds, since the copy is shallow.

```swig
{% set page_title = "Home" %}
{% set items = ["a", "b", "c"] %}
```

Assigning to reserved property names (`__proto__`, `constructor`, `prototype`) throws at parse time — see [Security](./security).

## spaceless

Remove whitespace between HTML tags in the enclosed region.

```swig
{% spaceless %}
  <p>
    <a href="/">Home</a>
  </p>
{% endspaceless %}
{# => <p><a href="/">Home</a></p> #}
```

Only whitespace between `>` and `<` is stripped — text content is preserved.
