# Django Parity

This page lists exactly what `@rhinostone/swig-django` accepts — operators, variable resolution, tags, and filters — cross-referenced against Django Template Language (DTL) and the native `@rhinostone/swig` frontend.

The matrices below are ground truth: each row maps to a symbol actually exported by the shipped source, and every filter was cross-checked against Django 5.2's `defaultfilters.py`. Outputs match the reference except where the JavaScript runtime forces a divergence — those are flagged here and detailed under [Behavioural differences](#behavioural-differences). For features that throw at parse time, need the framework runtime, or are deferred, see [Non-Goals](./non-goals).

## A lenient superset of DTL

The expression grammar is a **lenient superset** of Django's. It keeps the inherited expression machinery (parentheses, arithmetic, comparisons) and adds the Django pieces (colon-filters, `True`/`False`/`None`, `is`/`is not` identity). Every valid Django template renders; the engine *also* accepts a handful of non-Django expressions — `{{ a + b }}`, `{{ (a or b) and c }}` — that real DTL never contains (Django has no arithmetic operators and no parentheses inside `{% if %}`). That extra acceptance is harmless: a valid Django template never uses those forms, so they cost nothing in fidelity. The tag and filter catalogs, by contrast, are **subsets** — the framework-coupled tags need a Django runtime swig-core does not provide (see [Non-Goals](./non-goals)).

## Operators

| Operator | Shape | Semantics | Lowering / notes |
| --- | --- | --- | --- |
| `\|name:arg` | colon-filter | Apply a filter with one positional argument — Django's filter-argument syntax. | The backend emits positional filter args; `\|date:"Y-m-d"` and `\|truncatewords:2` lower the same way. |
| `==` `!=` `<` `>` `<=` `>=` | comparison | Standard comparisons. | |
| `and` `or` `not` | logic | Short-circuit boolean logic. | |
| `in` / `not in` | `x in seq`, `x not in seq` | Membership, as in Django (since 2.9.0): a list holds an equal item, a string a substring, a mapping a key. A test Django cannot run, such as a number as the container, is false for both `in` and `not in`, as in Django. Some answers still differ — see [Behavioural differences](#behavioural-differences). | `_utils.isIn(x, seq, "python")`; `not in` binds at the same level as `in`. |
| `is` / `is not` | `x is None` | Identity comparison (`===` / `!==`), **not** a Jinja2-style test. | `is None` / `is not None` route through the existence check so a missing value is distinguished from a real one. See [The `is` operator](#the-is-operator). |
| `True` `False` `None` | literals | Python-style boolean and null literals. | Lower to JavaScript `true` / `false` / `null`. |
| `( )` | grouping | Parenthesised sub-expressions (lenient — real DTL `{% if %}` has no parens). | |
| `+` `-` `*` `/` `%` | arithmetic | Accepted (lenient — real DTL has no arithmetic operators). `+` concatenates when either side is a string (JavaScript coercion). | Use the `add` filter for Django-faithful addition. |

Django's auto-calling of callables (no `()` needed — `{{ user.get_full_name }}`, not `{{ user.get_full_name() }}`) is part of [variable resolution](#variable-resolution), not an operator.

## The `is` operator {#the-is-operator}

In Django, `is` is an **identity comparison** — `{% if x is None %}`, `{% if flag is True %}` — not Jinja2's predicate-test mechanism (`x is defined`, `x is odd`, …). `@rhinostone/swig-django` matches Django:

| Shape | Semantics |
| --- | --- |
| `x is None` | `true` if `x` is absent or `null` (routed through the existence check, so a missing context slot is distinguished from a real value). |
| `x is not None` | `true` if `x` is present. |
| `x is True` / `x is False` | Strict equality against the boolean. |
| `x is y` | Strict identity (`x === y`). Distinct object references are **not** identical (`{} is {}` → false). |

Jinja2-style tests are **not** registered. `{% if x is defined %}` does **not** test definedness — it compiles to `x === defined`, comparing `x` against an (undefined) variable named `defined`, which is almost never what you want. There is no `is odd` / `is iterable` / `is mapping`. This is faithful to Django, which has no test system; if you are porting from Jinja2, see [Non-Goals → Jinja2-style `is` tests](./non-goals#jinja2-style-is-tests).

## Variable resolution {#variable-resolution}

`{{ a.b.c }}` resolves each segment with Django's lookup algorithm, via the shared `swig-core` resolver (opt-in for this frontend; native/swig-twig/swig-jinja2 keep the plain dot-path):

1. **Dictionary lookup** — `obj["seg"]`.
2. **Attribute / method lookup** — `obj.seg`; if the result is a **function**, it is **auto-called** with no arguments (bound to its receiver) and the return value is used.
3. **Numeric index** — `{{ items.0 }}` resolves `items[0]` (JavaScript indexes arrays and strings by numeric string key, so one access covers all four cases).

```django
{{ user.get_full_name }}   {# calls user.get_full_name() — no parens #}
{{ items.0 }}              {# first element #}
{{ matrix.1.2 }}           {# nested index #}
```

Auto-call opt-outs match Django:

| Function flag | Effect |
| --- | --- |
| `fn.alters_data === true` | Not called — resolves to `undefined` (renders `""`). Mirrors Django's `alters_data`. |
| `fn.do_not_call_in_templates === true` | Returned **uncalled** (the function value itself). Mirrors Django's `do_not_call_in_templates`. |

A call that throws resolves to `undefined` (renders `""`), mirroring Django's `string_if_invalid` default. Every segment is still checked against the prototype-chain (`_dangerousProps`) blocklist at parse time, and the resolver re-checks at runtime as defence in depth — `{{ a.__proto__ }}` throws.

## Tags

`@rhinostone/swig-django` ships **12 built-in tag families** (`elif`, `else`, and `empty` are branch markers consumed by `if`/`for`, not standalone tags). Each is registered in `packages/swig-django/lib/tags/index.js`.

| Tag | Ends | Notes |
| --- | --- | --- |
| `if` / `elif` / `else` / `endif` | Yes | Full multi-branch conditionals, including `elif` chains and `and`/`or`/`not`/`in`/`is` conditions. |
| `for` / `empty` / `endfor` | Yes | `forloop.counter`/`counter0`/`revcounter`/`revcounter0`/`first`/`last`/`parentloop`, empty-fallback `{% empty %}`, and dict pseudo-methods `{% for k, v in d.items %}` / `d.keys` / `d.values`. One loop variable over a dict binds each key and two over a list unpack each item, as in Django, so `{% for k, v in pairs %}` binds the key and the value (since 2.9.3; before, one variable over a dict bound each value and two over a list bound the index and the item). Two loop variables over a dict give the key and the value, a swig extension (see [Behavioural differences](#behavioural-differences)). Since 2.9.9, as in Django, a mapping's own `items`, `keys` or `values` key is read before the dict method of that name, one loop variable over `.items` binds each key and value as a pair (`{{ pair.0 }}={{ pair.1 }}`), and over a list, a string, a number or a boolean the three names run no item; before, the tag rewrote the three names, so such a key was never read and one loop variable over `.items` failed to compile. The `reversed` modifier is [deferred](./non-goals#deferred-tag-forms). Loop variables containing `.` are rejected (prototype-chain guard). |
| `block` / `endblock` | Yes | Named block for template inheritance. `{% endblock name %}` accepted. `{{ block.super }}` is [deferred](./non-goals#deferred-tag-forms). |
| `extends` | No | Static (`{% extends "base.django" %}`) and dynamic (`{% extends layout_var %}`) — the dynamic form resolves on the [async render path](../swig/loaders#async-loaders); the synchronous path requires a string literal. See [Non-Goals](./non-goals#dynamic-extends). |
| `include` | No | `{% include "partial.django" %}` with Django's space-separated `with k=v` context and trailing `only` for isolation. No `ignore missing` (Django raises) — see [Behavioural differences](#behavioural-differences). |
| `with` / `endwith` | Yes | Both forms: modern `{% with a=1 b=2 %}` (space-separated pairs) and legacy `{% with expr as name %}`. |
| `autoescape` / `endautoescape` | Yes | `{% autoescape on %}` / `{% autoescape off %}` — Django's `on`/`off` spelling, not boolean literals. |
| `spaceless` / `endspaceless` | Yes | Collapses whitespace **between** HTML tags (`>\s+<` → `><`) within the block only. Narrower than native swig's `spaceless` — see [Behavioural differences](#behavioural-differences). |
| `comment` / `endcomment` | Yes | Discards the body unparsed (broken tag syntax inside is safe). Optional `{% comment "note" %}` label accepted and ignored. |
| `verbatim` / `endverbatim` | Yes | Verbatim content; variable, tag, and comment syntax pass through untouched. |
| `cycle` | No | `{% cycle "a" "b" "c" %}` — cycles through values across loop iterations, with independent state per occurrence. The `as name` / named-reuse / `silent` forms are [deferred](./non-goals#deferred-tag-forms). |
| `firstof` | No | `{% firstof a b c %}` — outputs the first truthy argument (or `""`). The `as var` form is [deferred](./non-goals#deferred-tag-forms). |

There are **no** `macro` / `import` / `from` tags — Django has none either. Compose with `{% include %}`, `{% block %}`, and `{% extends %}`. The framework-infrastructure tags (`{% url %}`, `{% load %}`, `{% static %}`, `{% csrf_token %}`, `{% trans %}`, `{% blocktrans %}`) throw `Unexpected tag "<name>"` at parse time — see [Non-Goals → Framework infrastructure](./non-goals#framework-infrastructure).

## Filters

`@rhinostone/swig-django` ships **42 built-in filters** (43 callable names counting the `e` alias of `escape`). They live in `packages/swig-django/lib/filters.js`. Every filter below was cross-checked against Django 5.2.

Since 2.9.13 the string filters read a `None` value as the text `None`, as Django does: `{{ x|upper }}` with `x` `None` renders `NONE` and `{{ x|title }}` renders `None` (before, `[object Object]` and `Null`). So does a variable that fails to resolve where Django reads it as `None` (`if`, `for`, `firstof`): `{% if user.role|lower == "admin" %}` over a missing role takes the else branch (before, it failed), and `{% for c in x|make_list %}` over a missing `x` walks `None` (before, `undefined`). `escape`, `escapejs` and `safe` keep the empty string of `{{ x }}`, where Django prints `None`.

### Safe filters

These bypass autoescape (the autoescape `e` tail is not appended) — exactly six: **`safe`**, **`escapejs`**, **`force_escape`**, **`linebreaks`**, **`linebreaksbr`**, **`linenumbers`**. The three `linebreak*` / `linenumbers` filters escape their text content *before* wrapping it in markup, so marking them safe is XSS-correct. `escape` / `e` are **not** `.safe` (idempotency, not a flag, prevents double-escaping), and `floatformat` is deliberately **not** `.safe` — its error path returns the raw input, so a blanket safe flag would be an XSS hole (its numeric output carries no HTML, so the redundant escape is a harmless no-op). Filters that emit already-safe HTML you register yourself must set `.safe = true` on the function.

This is **not** the same as Django's `is_safe=True`: in Django, `is_safe` only marks that a filter *preserves* an already-safe input; only filters Django wraps in `mark_safe()` should carry swig's `.safe = true`.

### Registering your own

```js
django.setFilter('exclaim', function (input) { return String(input) + '!'; });
django.render('{{ msg|exclaim }}', { locals: { msg: 'hi' } });
// → "hi!"
```

```js
function monospace(input) { return '<code>' + input + '</code>'; }
monospace.safe = true;
django.setFilter('monospace', monospace);
```

See [Extending Swig](../swig/extending) for the full filter/tag extension contract — it is identical across frontends.

## Behavioural differences

These behaviours are **supported** but diverge from Django because the JavaScript runtime (or the shared swig-core engine) differs from CPython. None of them throw — they just behave differently:

| Area | Django | `@rhinostone/swig-django` |
| --- | --- | --- |
| `{% for k, v in d %}` over a dict, without `.items` | Iterates the keys and unpacks each one, so it raises unless every key has two characters. | Gives the key and the value, as `{% for k, v in d.items %}` does. |
| `{% for k, v in items %}` where an item does not hold two values | Raises a `ValueError` (`Need 2 values to unpack in for loop`). | Binds what the item holds (since 2.9.3): a missing value renders empty, extra values are ignored, and an item that is not a list, a string or a mapping binds nothing. |
| `forloop.length` | No such field. | Present (swig exposes it) — harmless extra acceptance. |
| `default` on `""` | Substitutes (the value is falsy). | Same — substitutes. A variable that fails to resolve reaches its filters as `""`, as Django gives it `string_if_invalid`, so `default` fires on it too. Since 2.9.9 every filter gets it that way; before, the others received `undefined`, so `{{ missing\|upper }}` threw and `title` rendered `Undefined`. |
| `{{ True }}` / `{{ False }}` | Render `"True"` / `"False"`. | Render `"true"` / `"false"` (JavaScript booleans). Rarely output directly; in conditions they behave correctly. |
| `{{ None }}` | Renders `"None"`. | Renders `""` (engine null-coercion). |
| `{% include %}` `ignore missing` | Not a thing — a missing include raises. | Also raises (no `ignore missing` clause); Django-faithful. |
| `spaceless` | Strips whitespace between tags across the whole rendered block. | Same intent, region-isolated: only the block's own `>\s+<` runs collapse — narrower than native swig's whole-`_output` mutation. |
| `floatformat` | `mark_safe`s the success path only. | Not marked safe (the error path returns raw input); numeric output carries no HTML, so output is identical. |
| Object stringification | Python `str()` / `repr()`. | JavaScript `String(x)` — objects without a custom `toString` render `"[object Object]"`; `null` / `undefined` render `""`. |
| `date` / `time` | `strftime`-style format codes, locale-aware. | PHP-style codes via the shared `swig-core` formatter; no locale plumbing. Pass an explicit format string. |
| Characters outside the Basic Multilingual Plane, such as an emoji | Count as one character. | Count as two: `length` gives 2, and `first`, `last`, `make_list`, `slice` and `truncatechars` can split one into invalid halves. |
| `in` and `not in` | Python equality: `True in [1]`, `0 in [False]` and `[1, 2] in [[1, 2]]` are true, and `1 in {'1': 'x'}` is false. `not x in y` is `not (x in y)`. | Membership as in Django since 2.9.0, except: a boolean and a number are different items and a list or a mapping inside a list matches only the same object, so those three are false; a number tests a mapping key with the same digits, so `1 in {"1": "x"}` is true. `not x in y` is `not (x in y)`, as in Django (since 2.9.9; before, `not` bound only the name after it, so it read `(not x) in y`). |

See [Migrating from Django](./migration) for the porting view of these.

## Autoescape

Autoescape behaves as in native swig — `true` by default, applies the `e` filter last, honours `.safe = true` on filter exports. The built-in safe filters (the six listed above) are excluded. `{% autoescape off %}…{% endautoescape %}` disables it for a region using Django's `on`/`off` spelling.

See [Security — what the guards protect against](../swig/security#what-the-guards-protect-against) for the full prototype-chain guard matrix — it applies uniformly across frontends because the guards live in `swig-core`'s shared backend.
